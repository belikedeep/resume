# Skills Section Guidelines

shoutout to u/0ffkilter

---

## Objective

- The purpose of the skills section is to highlight in a few words what technical skills you can bring to the job
- Ideally, these match the job description
- They can also include other technical skills that are related, but perhaps not necessarily in the job description
- If you are applying to a job that's in Java, saying you also know C++ can be useful
- This is not a section to spew every buzzword on every technology you've ever touched
- Find a balance between enough skills while not showing too many so that none seem important

---

## Naming

- This section should simply be named **Skills**
- Do not use:
  - "Technical Skills"
  - "Relevant Skills"

---

## You Should

- Include languages you've used thoroughly and could theoretically interview in
- Include technologies (frameworks, tools, programs) you've used previously
- Repeat things that you use in your bullet points
  - If Java is in skills, it should appear in experience
  - And vice versa

---

## You Should Not

- Include soft skills (teamwork, leadership, etc)
- Include assumed skills (typing, Microsoft Word, IDEs, etc)
- Generally do not include:
  - Code repository websites (use Git, not GitHub/GitLab/Bitbucket)
  - Operating Systems
  - IDEs or editors (VS Code, LaTeX, vim, etc)

---

## Formatting

- Easy to read and digest
- Each skill should feel important

### You Should

- Use 3 lines or less
- Use single-column format
- Order skills from most important to least important
- Evaluate if weaker skills should be removed
- Separate skills into categories:
  - Languages
  - Technologies
  - Design Tools
  - etc

- Use proper formatting:
  - Separate with commas
  - Capitalize properly (e.g. SolidWorks, CATIA V5, LabVIEW)
  - Separate similar skills (C, C++ not C/C++)

---

### You Should Not

- Bold random words
- Use descriptors like "Expert in"
- Use multiple columns

---

## FAQs

### Should I include random hobbies?

- No
- If included, use a separate section only if necessary

---

### Should I include skills I'm not comfortable with?

- Judgment call
- Fewer strong skills > many weak skills
- Balance depth vs breadth
